ELSTAT publishes the household budget survey twice: as tables (table 1.03 gives every item's average monthly spending) and as a public file of the households themselves, each with a weight that says how many households it stands for. Added up with those weights, the file should give the table's figures exactly.

## What happened

- **In fourteen of the seventeen years (2008–2013, 2016, 2017, 2019–2024)** it does: every item matches to the cent, apart from the few items the public file leaves out or cuts (tolls, life insurance, "various services" and a few more), and the households add up to the table's number. Where the table splits households into bands we can rebuild (2010–2013), every band matches too.
- **In 2014, 2015 and 2018** the file's weights add up to another number of households than the table gives:

| Year | Households, published table | Households, public file | Difference |
|---|---|---|---|
| 2014 | 4 152 372 | 4 136 073 | −0.4% |
| 2015 | 4 124 095 | 4 134 481 | +0.3% |
| 2018 | 4 085 310 | 4 048 749 | −0.9% |

- In those years most items differ, by little: half of the differences are under 1% of the item's value (under 2% in 2018), typically 4 to 7 cents a month. Two items of 2015 (clothing materials and furniture repair) have no column in the file at all.

## What we know, and what we don't

The pattern points to the weights: in every year whose weights add up to the table's households, the same reading of the file gives the table's figures. The likeliest reading is that the file and the table were made with different weights, for instance one of them weighted again after the other was made. ELSTAT hasn't said so, nor which version it considers final, so the cause is marked as not known.

## What we tried

- **Every year's file, the same way.** The same code reads all seventeen files; fourteen match the table to the cent, so the reading itself isn't the cause.
- **Which years differ.** The three years with differences are exactly the three whose weights add up to another number of households than the table's.
- **Whether the totals alone explain it.** They can't: multiplying every weight by the same factor leaves every average unchanged. So the weights differ household by household, not only in their total.

## What would settle it

ELSTAT saying which weights are final, or a later version of either the file or the table that brings the two back together.

## What we do

Our groups' spending shares start from the file's weights, since each file is consistent with itself, and only scale them so renters make up the census's share (see the method). The inflation-by-group method lists this among the points ELSTAT has not confirmed. Every figure compared is in the check's download.
